# Skill: оценка требований тендера

Применяй в отдельном AI-узле после [сбора источников](collect-tender-context.md) и проверки полноты пакета обычным шагом n8n. Вход: полученные политика, профиль компании, состав пакета и ответы чтения документов. Используй данные источников из `structuredContent`.

## Порядок оценки

1. Сверь идентификаторы и версии источников. Убедись, что для каждого обязательного документа передан ответ чтения из нужного пакета.
2. Возьми перечень `criterion_id` из политики и оцени каждый критерий. Требования извлекай из документов заказчика, возможности компании из её профиля.
3. Проверяй режим поддержки и срок реакции независимо. Поддержка 24×7 сама по себе не определяет срок реакции. Условия похожих проектов не заменяют требования текущего заказчика.
4. Для каждого вывода выбери статус по правилам ниже, объясни основание и приложи ссылки.
5. Верни один JSON-объект с указанными полями.

| Статус | Когда применяется |
|---|---|
| `match` | Требование заказчика и соответствующая возможность компании подтверждены источниками |
| `mismatch` | Источники подтверждают противоречие между требованием заказчика и возможностью компании |
| `needs_clarification` | После полного просмотра обязательных документов и профиля сведений недостаточно для сравнения |

Для `needs_clarification` сформулируй конкретный вопрос владельцу недостающих сведений. Если требование не найдено, перечисли все проверенные документы. Для остальных статусов `clarification_question` равен `null`.

## Основания

Для разделов документов используй возвращённые `source_ref`. Для сравнения с компанией укажи также поле профиля в формате `<company_id>/<profile_version>#<field_path>`. Идентификаторы, версии и пути к полям бери из входных данных.

`match` и `mismatch` требуют основания с обеих сторон сравнения. Непрочитанный обязательный документ блокирует итоговую оценку.

## Формат результата

- `tender_id`, `package_version`, `company_id`, `profile_version`, `policy_id`, `policy_version`: значения из полученных источников.
- `reviewed_documents`: массив объектов с `document_id` и `document_version` для фактически прочитанных документов.
- `findings`: по одному объекту на критерий политики, поля `criterion_id`, `status`, `reason`, `evidence` (массив строк), `clarification_question` (строка или `null`).
- `error`: `null`, если исходные данные позволяют выполнить оценку; строка с описанием проблемы, если обнаружена ошибка источника или неполный обязательный пакет. В таком случае `findings` должен быть пустым массивом.

При штатной работе неполный пакет должен быть остановлен до этого AI-узла. Проверку JSON, полноты критериев, ссылок и сохранение выполняет обычный шаг n8n. Поле `error: null` не означает, что результат прошёл эти проверки или был сохранён.
