# Skill: сбор источников тендера

Применяй в AI Agent перед оценкой тендера. Задача этого узла: получить источники через [MCP toolkit](../toolkit.md) и показать фактически выполненные действия.

Вход: `tender_id`, `package_version`, `company_id`, `profile_version`, `policy_id`, `policy_version`. Идентификаторы документов бери из полученного состава пакета.

## Порядок действий

1. Вызови `get_evaluation_policy` и `get_company_profile` с заданными идентификаторами и версиями. Сверь идентификаторы и версии в ответах с запросом.
2. Вызови `list_tender_documents` для выбранного пакета. Сохрани список пар `document_id + document_version` и признаки `required`.
3. Вызови `read_tender_document` для каждого документа из списка. Для каждого ответа сверь документ, версию и принадлежность выбранному пакету; сохрани полный текст, разделы и ссылки.
4. Сопоставь список пакета с успешными чтениями. Повторное чтение одной пары не покрывает другую. Если политика задаёт `all_package_documents_required=true`, обязательны все документы из списка; иначе учитывай их признаки `required`.
5. В текстовом ответе кратко перечисли полученные источники и версии, критерии политики и разделы прочитанных документов. Для оставшихся документов укажи, что произошло: вызов пропущен либо инструмент вернул конкретную ошибку.

## Когда сбор закончен

Политика, профиль и состав пакета успешно получены с нужными версиями. Для каждого обязательного документа есть успешный ответ чтения с согласованными метаданными. Проверка опирается на ответы инструментов.

Если обязательный источник не получен, перечисли недостающие источники и заверши сбор как неполный. Отсутствие вызова означает «чтение не выполнялось». Ошибка чтения означает, что вызов был, но источник получить не удалось. Ни один из этих случаев не доказывает отсутствие требования в документе.

## Передача результата

Оценка соответствия выполняется отдельным узлом после проверки полноты. Для передачи данных в n8n включается `Return Intermediate Steps`: следующий шаг получает данные из `observation` / `structuredContent`, а не пересказ из `output`. Журнал `messageLog` для анализа источников не нужен.

Полноту дополнительно проверяет обычный шаг workflow. Эта инструкция описывает поведение агента и сама по себе не обеспечивает выполнение всех вызовов.
