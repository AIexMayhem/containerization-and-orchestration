# Toolkit для проверки тендера

У агента четыре инструмента на двух MCP-серверах. Все операции дают только чтение. Контракт реализован в [servers.py](mcp-services/tender_mcp/servers.py) и [sources.py](mcp-services/tender_mcp/sources.py).

| Инструмент | MCP-сервер | Действие и результат | Обязательный вход |
|---|---|---|---|
| `list_tender_documents` | `tender-documents` | Возвращает состав пакета: `document_id`, `document_version`, `required` для каждого документа | `tender_id: string`, `package_version: string` |
| `read_tender_document` | `tender-documents` | Возвращает полный `text`, принадлежность пакету и `sections` с полями `section_id`, `title`, `text`, `source_ref` | `document_id: string`, `document_version: string` |
| `get_company_profile` | `company-reference` | Возвращает профиль компании с идентификатором, версией, возможностями и ограничениями | `company_id: string`, `profile_version: string` |
| `get_evaluation_policy` | `company-reference` | Возвращает политику с идентификатором, версией, критериями и правилами оценки | `policy_id: string`, `policy_version: string` |

## Подключение

Из контейнера n8n серверы доступны по адресам:

- `tender-documents`: `http://host.docker.internal:8001/mcp`;
- `company-reference`: `http://host.docker.internal:8002/mcp`.

Транспорт HTTP Streamable, Authentication None для локального стенда. В каждом MCP Client выбраны оба инструмента соответствующего сервера. n8n добавляет к имени инструмента префикс из названия узла; в таблице указаны исходные имена MCP.

## Правила контракта

- Все параметры обязательные. Идентификаторы и версии имеют длину 1–64 символа, начинаются с латинской буквы или цифры, далее допускаются также `_` и `-`. Пути к файлам на вход не принимаются.
- Версия задаётся явно. Сервер возвращает запрошенную версию или ошибку, автоматической подстановки другой версии нет.
- Список пакета содержит метаданные. Текст получают отдельным вызовом `read_tender_document` для каждой пары `document_id + document_version`. Размеры файлов и пути в ответ списка не входят.
- Ответ чтения содержит `tender_id` и `package_version`: их нужно сверить с выбранным пакетом. Неоднозначная пара документа и версии приводит к `AMBIGUOUS_DOCUMENT`.
- Готовые `source_ref` возвращаются у разделов документов. Для ссылки на поле профиля в результате оценки используется запись `<company_id>/<profile_version>#<field_path>`, составленная из полученных данных.
- Недоступный или некорректный источник возвращает ошибку инструмента. Пропущенный вызов фиксируется отдельно: утверждать, что сервер вернул ошибку, можно только по фактическому ответу.

В n8n ответы инструментов доступны при включённом `Return Intermediate Steps`. Поле `observation` разбирается как JSON; данные источника находятся в `structuredContent`. Текстовый `output` агента служит пересказом, а полноту пакета проверяют по успешным ответам инструментов.
